The Problem

会写，但不可控

大多数 AI 叙事 demo 的通病：

  • 情绪忽高忽低，每年都有大事
  • 结尾变鸡汤，缺乏真实遗憾
  • 用户介入不影响后续——按钮是假的
  • 生成失败后无法复盘，只能重 roll
Shadow 的核心思路：把创作拆成受约束的生产线。模型负责「写」，Harness 负责结构、记忆、反馈和停止条件。
我们不是在做一个会写故事的 AI，而是在做一个能被干预、能记住、能复盘、能持续变好的叙事 Agent Harness。

Agent Pipeline

五步成文，逐年推进

Persona→ Beats→ Year×7→ Final→ Dialogue

Persona · 人格卡

软肋、决策倾向、成长种子——决定后续七年的心理动力。

Beats · 七年节奏

2–3 个 pivotal 年，其余 quiet 年，避免「年年大事」。

Year · 逐年生成

每次只写一年：读人格、memory、时代背景与用户介入。

Final · 收束

不复述剧情，必须有 regret，不写「另一条路也好」。

Dialogue · 跨时空对话

随时问影子；回答必须引用 memory_stream，像走过七年的人。

增强层：Fate Agent（时代语料）· Scene Agents（六域 lens）· RAG Kit（记忆检索）

User Intervention

岔路口，不是 UI 假按钮

在 pivotal 年，用户可以选择影子的下一步。这条选择会：

  • 写入 session，成为「已发生事实」
  • 进入下一年 Year Agent 的 prompt 上下文
  • 沉淀进 memory_stream，供 Final 与 Dialogue 引用
quiet 年必须短、pivotal 年才重；pivotal 年才有 intervention 弹窗；用户选择下一年不能忽略——这些由 evaluator 规则强制，而非靠模型自觉。

Quality Gates

三道门，不靠感觉

① Schema

Zod 契约强制 Persona、Beats、Year、Final、Dialogue 字段结构——生成即合法 JSON。

② Evaluator

规则检查 pivotal 数量、quiet 长度、介入位置、memory 抽象度、final 鸡汤等反模式。

③ Golden Story

「复读线」作人工标定样本；prompt 改动必须过 eval，防止核心体验漂移。

每次 live run 落盘 trace：stage、intervention、eval、stop_reason——失败可复盘，不是黑盒重 roll。
